# Qwen Desk 1.0.0 验证记录

验证日期：2026-10-21。该记录对应项目源码、Windows x64 NSIS 安装包和真实模型运行结果。测试日志、下载权重、临时配置及浏览器配置不进入交付包。

## 环境与依赖

- 系统：Windows 11 Pro x64，10.0.26300，已安装 Microsoft Edge WebView2。
- GPU：NVIDIA GeForce RTX 4060 Laptop GPU，8 GB 显存，使用 Vulkan；另已实际执行 CPU 推理。
- 显示器：主屏 2560×1600，左侧副屏 2160×1440；本次窗口验证时 DPI 为 144（150%）。
- 原生后端：官方 llama.cpp b11796，提交 0a1ef309c。CPU/Vulkan 运行库随安装包安装。
- 编译：Rust MSVC、Visual Studio C++ 工具链、Node.js、npm、Tauri 2；依赖版本由 Cargo.lock 与 package-lock.json 固定。

## 真实推理与资源生命周期

- 两个默认模型均在 NVIDIA Vulkan 后端加载成功；生成请求将“你好，世界。”翻译为 `Hello, world.`。
- 生成模型在 CPU 后端也完成相同翻译；不是仅检测到 CPU 可执行文件。
- 默认向量模型在 Vulkan 与 CPU 均返回实际 1024 维有限浮点数向量，L2 范数接近 1，包含真实 tokenizer 使用量。批量两个输入、128 维截断重新归一化及 base64 输出通过验证。
- 缺少 GPU 运行库时自动切换到 CPU，并返回实际向量；状态包含降级说明。
- 同时运行生成与向量模型，互相独立卸载。重复切换向量模型注册及重复卸载通过验证。
- 额外下载官方 `Qwen/Qwen3-0.6B-GGUF/Qwen3-0.6B-Q8_0.gguf`，通过界面从默认 4B 生成模型切换到该 0.6B 模型，实际返回 `Hello, world.`；再切回默认 4B 模型并重新完成翻译。原进程被回收，临时模型文件和注册在验证后删除。
- 另下载 `nomic-ai/nomic-embed-text-v1.5-GGUF/nomic-embed-text-v1.5.Q8_0.gguf`，从 Qwen 向量模型切换到不同架构的 Nomic 模型。两个输入均返回 768 维有限向量，L2 范数分别约为 0.999999977 和 1.000000006；切回 Qwen 后重新得到 1024 维有效向量。临时文件和注册均已删除。
- 正在执行的生成请求可以取消；HTTP 断开、模型卸载和停止服务都会释放活动请求。取消后不继续发送已缓冲的模型分片。
- 单线程 CPU 工作负载用于稳定触发真实 5 秒超时：流式响应返回结构化 `timeout` 错误和 `[DONE]`，非流式响应返回 504；随后新请求成功。
- 非法 GGUF 在原生解析阶段失败并被回收。加载取消时仍可轮询状态，模型进程能够终止。
- 多轮加载/卸载以及应用退出后检查进程列表，没有残留的本产品 `llama-server` 进程。Windows Job Object 为异常退出提供额外的子进程回收保障。
- 另实际终止验证宿主进程，两个原生推理子进程随 Windows Job Object 退出，API 监听也被释放。HTTP 验证脚本已在 Windows PowerShell 5.1 下针对真实模型服务复测通过；脚本使用 ASCII 编码构造中文输入，避免系统默认编码造成乱码。

## 安装、卸载及首次启动

NSIS 安装与卸载均返回退出码 0。应用安装到当前用户目录，原生推理子进程路径位于该安装目录的 `runtime/vulkan`，不依赖源码目录的引擎或开发服务器。从 Windows 目录启动仍能加载已下载模型并提供实际 HTTP 推理。

卸载后主程序和本产品开机启动项消失，用户设置文件哈希保持不变；重装后设置及模型继续可用。已比较安装后的主程序与该安装器解包出的主程序 SHA-256，二者一致。Tauri 会为安装器载荷写入 NSIS 包类型标记，因此不以未打包构建目录中主程序的哈希代替安装器载荷哈希。

另在关闭全部应用和推理进程后，将原应用数据目录临时隔离，启动最终安装版进行空配置验收：两个默认模型配置存在，模型文件状态为缺失，服务默认 `127.0.0.1:8848` 且停止，开机启动关闭，关闭窗口默认隐藏到托盘，凭据状态为缺失，无启动错误。五路由均可使用。验收后恢复原数据目录，并重新核对两个默认模型的 SHA-256。

## 验证边界与降级条件

- 当前实测为 Windows 11、NVIDIA Vulkan、CPU、双屏及 150% DPI。未将结果外推为所有 AMD/Intel 驱动、所有 GGUF 架构、Windows 10 或混合 DPI 组合均已实测。模型替换需满足当前 llama.cpp 的架构、chat template 或序列向量输出要求。
- 未刻意耗尽整机显存/内存；GPU 初始化/加载失败路径会尝试 CPU，识别到内存不足时给出安全错误。大模型和极长上下文仍需要足够的系统内存，CPU 回退不能消除模型本身的内存需求。
- 未重启或注销正在使用的 Windows 会话。开机启动验收包含真实 Run 注册、引号与参数读回、启停/卸载清理及启动参数执行；登录时的触发由 Windows 负责。
- 本机已有 WebView2；缺失 WebView2 的全新系统需要安装器下载微软引导程序，该条件路径未在此机器卸载系统组件后重测。
- 已检查原生 EXE/DLL 的 PE 导入表：需要 Windows UCRT、MSVCP140、VCRUNTIME140/140_1；Vulkan 后端还需要显卡驱动提供的 vulkan-1.dll。本机均已具备。无 Visual C++ 运行库的系统需要按 README 先安装微软 x64 Redistributable；当前用户安装器不安装该系统组件。
- 生产包没有代码签名证书。系统信任提示由安装机器的策略决定。
